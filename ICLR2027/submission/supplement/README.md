# Supplementary release package

This directory contains the small, non-identifying evidence package that
travels with the ICLR draft.

- `reproducibility_inventory.csv` records the frozen run inventory.
- `table1_cells.csv` records the paired irrigation-cell quantities used in the
  manuscript. Its Flood rows supply audit metadata only; the gemma3:4b row is
  a clearly labelled B6-included sensitivity and is never a Table 3 release
  source. `cross_testbed_release_cells.csv` is the single canonical set of 14
  configuration rows behind Table 3.
- `fig1_rule_layers.csv`, `fig2_mechanism.csv`, and `fig3_consequence.csv` are
  the machine-readable source values behind Figures 2--4. The mechanism CSV
  retains the frozen records, while the active paper figure displays its two
  primary irrigation panels (A--B). `fig3_denominator_gap.csv` is the copied,
  executed-action data behind the active Figure 4 dumbbell plot;
  `fig3_consequence.csv` remains the source table
  containing both action readings for the declared sensitivity analysis.
  `fig4_per_seed.csv` freezes those 21 paired executed-action records inside
  the release package. `fig4_gap_intervals.csv` records the resulting paired
  conditional-minus-all intervals.
- `cross_testbed_summary.csv` and `table3_cross_testbed.tex` are generated by
  the active cross-testbed builder. They keep Flood as a secondary numerical
  boundary check rather than a same-status mechanism panel.
  `cross_testbed_provenance.json` joins each release contrast to its run counts,
  audit coverage, reflection-record alignment, B6 decision, and denominator
  policy so every Table 3 caption claim has a reviewer-facing source.
  `enforcement_pressure_source.json` pins the reported governance-pressure
  ranges and their handoff source.
- `WORLD_REWEIGHTING_DIAGNOSTICS.md` keeps the pooled and per-seed estimates
  separate for the full frozen stratification ladder.
- `FIGURE_REGENERATION.md` records the regeneration commands and their source
  boundary.
- `figure2_generation.sha256`, `cross_testbed_generation.sha256`, and
  `fig4_generation.sha256` bind each multi-file generated group; the release
  verifier rejects a partial promotion.
- `FIRST_ATTEMPT_LIMITATIONS.md` records the fields that are not available in
  the frozen corpus.

The package does not claim full bitwise reproduction of every historic run.
The source-run provenance limitations remain disclosed in the paper. The
supplement contains no private credentials, local paths, or identifying model
metadata.

## Flood boundary-check limitations

The Flood summary is a secondary boundary check, not a clean matched control.
The nine configuration rows have minimum audit coverage from 70.5% to 99.9%.
The release audit records differing manifest seed IDs across arms in six
configurations. These differences are why the Flood values are reported as
bounded descriptive ranges and are not used for mechanism transfer, dose-response,
or causal claims. The gemma3:4b B6 exclusion and its four-governed/five-
no-validator sensitivity are documented in the active cross-testbed summary.
