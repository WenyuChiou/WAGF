# AGENTS.md — `broker/` Core Package Rules

This directory contains the generic WAGF governance middleware (plus `broker/domains/` and `broker/tests/`).

## Hard Invariants (see `broker/INVARIANTS.md`)

1. **No reverse imports**: non-test code under `broker/` MUST NEVER import from `examples/`.
2. **Domain genericity (`TestDomainGenericity`)**: generic `broker/` modules (including `core/`, `run/`, `coupling/`, `components/`, `validators/`, `utils/`, `interfaces/`, `memory/`, `agents/`, `config/`; the test scans every generic subtree) MUST NOT hardcode flood, drought, or irrigation vocabulary outside documented allowlist entries. Domain logic belongs behind `DomainPack` (`broker/domains/protocol.py`) or `CouplingContract` (`broker/coupling/contract.py`).
3. **Audit single source of truth**: `trace_to_csv_row` and `compute_csv_fieldnames` in `broker/components/analytics/audit.py` govern both live export and `broker/tools/recover_csv_from_jsonl.py`. Keep new columns additive and key-gated unless an invariant says otherwise.
4. **Memory contract**: `MemoryEngine.retrieve()` implementations (`broker/components/memory/`) MUST preserve metadata (`MemoryRecord` dicts), except the documented `WindowMemoryEngine` exemption.
5. **Experimental fence**: `broker/components/coordination/`, `broker/components/orchestration/` and the social-feed parts of `broker/components/social/` (posts, follower network) are parked for follow-up multi-actor / social studies. Do not add new coupling from `broker/run/` or `broker/core/` into them during single-agent-type releases. The rest of `social/` is live (imported by `broker/__init__.py`, the context providers, `broker/simulation/environment.py` and the frozen flood runner, which uses `social/graph.py (NeighborhoodGraph)`); changes there must keep the frozen-guard tests passing.
6. **Governance leaves no trace (Invariant 7)**: given the same executed action and the same world outcome, everything an agent later remembers, reflects on or is shown must be the same whether or not governance stepped in. That covers memory text and every metadata value (importance, emotion, routine mark, type), reflection input, a reflection's importance and what triggers a reflection, retrieval order and which records are recalled, the first prompt of later periods, what other agents see, and what a coupled model receives beyond the executed action. Of what agents read, governance may change only the retry prompt of the current decision. It may also decide which action executes (the answer approved after a retry, or the default), and that action and its world outcome do carry forward. A default applied because no answer could be read counts as an intervention too. A physical or institutional rule that is part of the world, shown the same way with or without governance, is world text, not governance text. Intervention details belong in the researcher's audit output (the audit CSV and raw traces; some, such as retry-prompt text, are recorded only when an audit flag is on), never in what agents read. `memory.rejection_line_style: executed` (the default on `broker.run`; `ExperimentRunner` defaults to `explicit`, and a case config can set its own style, as the frozen irrigation configs do with `neutral`) is how the runner meets this for its own memory line. When you change memory, reflection, retry, prompt or social code, run `python -m broker.tools.check_governance_carryover <agent_types.yaml>` on a mock case whose first answers break a rule, so run A has a default row and a row approved after a retry (`--require any` accepts either). See `broker/INVARIANTS.md` for the full rules and for the frozen cases that do not meet it.

## Required Checks Before Committing `broker/` Edits

- `python -m pytest broker/tests/ --timeout=600 -q -k "not real_llm"` (`--timeout` needs `pytest-timeout`, installed by `pip install -e ".[dev]"`)
- Verify `broker/tests/test_framework_invariants.py` passes with zero new allowlist shortcuts.
