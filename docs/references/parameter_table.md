# Parameter table

> Generated. Do not edit by hand. Rebuild it with
> `python -m broker.config.parameter_table --write docs/references/parameter_table.md`;
> `--check` exits 1 when this file differs from what the code now produces.
> Source: `broker/config/parameter_table.py`.

This is the one place to read the numbers the broker reads from `agent_types.yaml`,
their ranges, and the default each piece of code applies. Every default below is read
from that code when this file is built, not copied. Some keys have more than one default
because two pieces of code apply different ones; each is listed with the code that uses it
and which runners reach that code.

**Reading the "Read by" column.** `broker.run` is the generic entry point. It reads only the
keys marked as reaching it. It builds a `WindowMemoryEngine`, which ignores `window_size`
when it retrieves and returns the last `retrieval_top_k` items, so on `broker.run` the memory
shown to the model is set by `retrieval_top_k`. Paper runners (single_agent, governed_flood,
irrigation_abm, multi_agent/flood) build their own memory engines and read more keys.

**Where a key can sit.** Keys under `memory` and `reflection` can sit in `global_config`, in the
legacy `shared` block, and in an agent block. The `governance` keys sit in `global_config`, or
in the legacy `shared.governance`. `llm_safeguard` sits in `global_config` only. The path in the
first column is the `global_config` form.

## The agent's action number

The number an agent attaches to its action (how much to release, how much to cut) is not a broker
key. A new case declares it as a numeric response field named `magnitude`, with `min: 0` and
`max: 1`, so 0.5 means half. The parser clamps the model's answer to that range and records a
warning, so the prompt must say "fraction". `validate_prompt` warns when such a field allows more
than 1, and `python -m broker.run --strict-keys` refuses it. Do not turn on `multi_skill` for a
case with a [0, 1] action number: its second action reads whole numbers only. How to declare the
field, and the scaffold flag that writes it: `docs/guides/HOW_TO_ADD_A_NEW_DOMAIN.md`, section
"The action number".

## 5. Where defaults come from

There is no single registry in the code. Each default is applied by one of these, and this document reads them all:

- Memory engines: `HumanCentricMemoryEngine.__init__` (`broker/components/memory/engines/humancentric.py`), `UniversalCognitiveEngine.__init__` (`broker/components/memory/universal.py`) and the registry factories (`broker/components/memory/registry.py`, `_register_builtins`).
- `AgentTypeConfig` accessors called on an empty config: `get_global_memory_config`, `get_reflection_config`, `get_retrieval_config`, `get_drift_config`, `get_population_governance_config`, `get_bridge_importance_config`, `get_governance_retries`, `get_governance_max_reports`.
- Model settings: `LLMConfig` and `_load_global_config` in `broker/utils/llm_utils.py`; `_DEFAULTS` in `broker/utils/llm_safeguard.py`.
- `broker.run`: `_DEFAULTS` and `DEFAULT_WINDOW_SIZE` in `broker/run/_entry.py`.
- Reflection: `ReflectionTriggerConfig` and `ReflectionEngine` in `broker/components/cognitive/reflection.py`.
- Named constants: `DEFAULT_RETRIEVAL_TOP_K` (`broker/components/context/providers.py`) and `DEFAULT_PROXIMITY_WINDOW` (`broker/utils/parsing/unified_adapter.py`).
- Two typed loaders, `MemoryConfigSpec` (`broker/config/agent_types/base.py`) and `MemoryConfig` (`broker/config/schema.py`), carry their own defaults (for example `window_size` 5 and `arousal_threshold` 0.5). No runner builds an engine from them.

Paper runners also pass their own literals when they read a key (for example `window_size` from a command-line flag, or `arousal_threshold` 0.5 or 1.0). Those literals live in the runners, which this table does not read.

**Accessors with no runner.** `get_drift_config` has no caller outside tests: the drift settings are read by no runner. `get_population_governance_config` and `get_bridge_importance_config` are read only by the multi_agent/flood runner, which uses the `echo`, `entropy` and `deadlock` thresholds and the resolution importances; no runner uses `quorum_threshold`.

**Never read.** `global_config.cognitive_config` is read by no code. Strict key checking reports it.

**Case inputs that are not broker keys.** The three FQL values used by the irrigation case (sigma 1.22, regret 2.22 and 1.54) are inputs of that case, not broker keys, and have no row.

**Physical setpoints.** Setpoints of a case, such as reservoir levels or release limits, are the case's own model values. They are declared in its coupling contract (`VarSpec` lower and upper limits, with units) or in its `parameters:` block. They get no broker row.
