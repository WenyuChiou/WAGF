# Broker package map

`broker/` is the framework package (`broker/__init__.py`, `__version__ = "0.6.0"`). Its top-level docstring states the contract: skill-based governance, memory engines, and reflection for coupled human-environment simulations, with all domain-specific content (flood, irrigation, ...) supplied by pluggable domain packs under `broker.domains`. The central orchestrator is `broker.core.skill_broker_engine.SkillBrokerEngine` (aliased `GovernedBroker` for backward compat); everything else in the package either feeds it (interfaces, config, memory, components) or plugs into it (domains, validators, coupling). For the decision-flow narrative see [ARCHITECTURE.md](../../ARCHITECTURE.md); for the contracts that must never break see [broker/INVARIANTS.md](../../broker/INVARIANTS.md).

Beyond the nine sub-packages mapped below, `broker/` also contains `validators/` (the governance validator implementations — see the governance section), `components/`-adjacent `utils/` (`ModelAdapter`, `load_agent_config`, `load_agents_from_csv`), `modules/`, `simulation/`, `tools/`, and `tests/` (framework-invariant tests live at `broker/tests/test_framework_invariants.py`).

## Sub-package responsibilities

### `broker/agents`
Agent protocols and the base agent implementation. `protocols.py` defines `AgentProtocol` / `StatefulAgentProtocol` / `MemoryCapableAgentProtocol`; `base.py` provides `BaseAgent`, `AgentConfig`, and the config dataclasses (`StateParam`, `Objective`, `Constraint`, `Skill`); `loader.py` builds agents from user YAML via `load_agents` / `load_agent_configs`.

### `broker/components`
The component library the engine composes: context building (`context/builder.py` — `BaseAgentContextBuilder`, `TieredContextBuilder`), memory engines (`memory/engine.py` — `MemoryEngine`, `WindowMemoryEngine`, `HumanCentricMemoryEngine`, plus `memory/registry.py::MemoryEngineRegistry`), governance registries (`governance/registry.py::SkillRegistry`, `governance/validator_registry.py::ValidatorRegistry`), social graphs and perception filters (`social/`), analytics and audit (`analytics/audit.py::GenericAuditWriter`, `analytics/observable.py::ObservableStateManager`), plus `events/`, `cognitive/`, `coordination/`, `orchestration/`, and `prompt_templates/`.

### `broker/config`
Typed configuration schemas and registries. `schema.py` validates agent-config YAML (`AgentTypeConfig`, `GovernanceRule`, `GovernanceProfiles`, `GlobalConfig`, `load_agent_config`); `agent_types/` holds the SA/MA-unified `AgentTypeRegistry` / `AgentTypeDefinition` (with `get_default_registry`); `memory_policy.py` defines `MemoryWritePolicy` (`LEGACY_POLICY` / `CLEAN_POLICY`).

### `broker/core`
The orchestration layer. `skill_broker_engine.py::SkillBrokerEngine` runs the six-step validator pipeline (schema → legality → physical feasibility → institutional compliance → advisory magnitude → theory consistency) with the retry loop in `_retry_loop.py` (up to 3 revisions, then the registry default skill executes so the simulation always advances). `experiment.py` exposes `ExperimentBuilder` / `ExperimentRunner`; `psychometric.py` is the framework registry (`register_framework`, `get_framework`, `PsychologicalFramework`, `ConstructDef`); `unified_context_builder.py` builds prompts (`UnifiedContextBuilder`, `create_unified_context_builder`). Note the lazy-import discipline: `import broker.core` must NOT pull `broker.domains.water.*` (Phase 6Q-F-1); water-namespace legacy re-exports go through PEP 562 `__getattr__`.

### `broker/coupling`
Domain-agnostic layer for coupling the governed decision loop to external numerical simulators through a verified contract. `contract.py::CouplingContract` / `VarSpec` enforce four numerical-correctness checks (units, cadence alignment with declared reductions via `reduce_series`, mutation direction, single `consumer_of_record` against double-counting). `adapter.py::EnvironmentCouplingAdapter` wraps a sim engine behind `SimulationEngineProtocol`/`SkillExecutorProtocol` so the runner injects it in place of the raw engine; `bmi_source.py` (`BmiComponent`, `BmiEventSource`) hosts CSDMS-BMI models; `flag.py::resolve_coupling_enabled` is the two-layer feature flag. The subtree is import-inert and carries zero domain vocabulary (enforced by `broker/tests/test_framework_invariants.py::TestDomainGenericity`).

### `broker/domains`
Pluggable domain packs. `protocol.py::DomainPack` is the single facade (~30 methods with defaults in `default.py::DefaultDomainPack`); `registry.py::DomainPackRegistry` is the lookup (`register`, `get_or_default`). `water/` is the reference pack: PMT / cognitive-appraisal / utility / financial frameworks, thinking checks, social specs, memory strategies. Since Phase 6Q-G there is NO auto-discovery — a domain registers only when its sub-package is explicitly imported.

### `broker/governance`
Rule-type definitions and per-agent-type validation. `rule_types.py` defines `GovernanceRule`, `RuleCondition`, `RuleCategory` (personal/social/thinking/physical/semantic), `RuleLevel` (`ERROR` blocks and triggers retry; `WARNING` only logs), and `ConditionType` (construct/precondition/expression/social); `type_validator.py::TypeValidator` checks skill eligibility per agent type against the `AgentTypeRegistry`. The package's `validate_all` / `get_rule_breakdown` and the category validators are lazy re-exports from `broker/validators/governance/` (where `PersonalValidator`, `SocialValidator`, `ThinkingValidator`, `PhysicalValidator`, `SemanticGroundingValidator` actually live).

### `broker/interfaces`
Dependency-injection protocols and value types — no logic, no domain coupling. Load-bearing modules: `skill_types.py` (`SkillProposal`, `ApprovedSkill`, `ExecutionResult`, `SkillBrokerResult`, `ValidationResult` — the currency of the whole pipeline), `environment_protocols.py` (`EnvironmentProtocol` and tiered/social variants), `simulation_protocols.py` (`SimulationEngineProtocol`, `SkillExecutorProtocol`), plus context types, perception config, rating scales, and lifecycle hooks (`PreYearHook`, `PostStepHook`, `PostYearHook`).

### `broker/memory`
The unified (v5) cognitive memory architecture, consolidating earlier v2–v4 engines: `unified_engine.py` (`UnifiedCognitiveEngine`, `UnifiedMemoryItem`), `strategies/` (pluggable surprise: `EMASurpriseStrategy`, `SymbolicSurpriseStrategy`, `HybridSurpriseStrategy`, `MultiDimensionalSurpriseStrategy`), `store.py::UnifiedMemoryStore`, `retrieval.py::AdaptiveRetrievalEngine`, `vector_db.py` (FAISS index) and `graph.py::MemoryGraph`. Any new engine must preserve memory metadata end-to-end — Invariant 1 in [broker/INVARIANTS.md](../../broker/INVARIANTS.md) (the `WindowMemoryEngine` content-only exemption is CLOSED to new members).

## Where do I add X

### A new domain
1. Create `broker/domains/<name>/__init__.py` with a module-level `register()` called at the bottom of the file — `broker/domains/water/__init__.py` is the reference: it calls `broker.core.psychometric.register_framework(...)` for each psychological framework, then registers thinking-validator metadata and social specs.
2. For full behavior overrides, implement a `DomainPack` (subclass `DefaultDomainPack` from `broker/domains/default.py` and override only what you need) and register it: `DomainPackRegistry.register("<name>", MyPack())` — the registry smoke-checks a small set of hot-path methods at registration time.
3. Consumers must import your sub-package explicitly (directly or via an example package such as `examples.governed_flood`); since Phase 6Q-G nothing auto-discovers domains, and tests that rely on registered framework names need an explicit `import broker.domains.<name>` line. Zero edits under core `broker/` code are required — that is the design goal stated in `broker/domains/protocol.py`.

### A new governance rule or validator
- **A new rule** is usually pure configuration: author a `GovernanceRule` in the agent-config YAML (validated by `broker/config/schema.py`, typed by `broker/governance/rule_types.py`) with conditions of type construct/precondition/expression/social and a level of `ERROR` (blocking, feeds the retry loop) or `WARNING` (logged only). Evaluation is dispatched by category through `broker.validators.governance.validate_all`.
- **A new domain-specific builtin check** registers through `broker/components/governance/validator_registry.py::ValidatorRegistry` under one of the honest slots `("physical", "personal", "social", "semantic", "thinking")`, in mode `active` or `shadow` — example packages register at their own `__init__` import time; broker looks checks up by `(domain, slot)` and never imports example modules. `broker/tests/test_declaration_consumption.py` enforces that every slot has a real dispatch site.
- **A new validator class** belongs in `broker/validators/governance/` (subclass `BaseValidator`; see `personal_validator.py` etc.), exported via that package's `__init__.py`. Per-agent-type eligibility stays in `broker/governance/type_validator.py::TypeValidator`.

### A new external-model coupling
1. Author a `CouplingContract` from `VarSpec`s (`broker/coupling/contract.py`): every exchanged variable declares unit, dtype, range, direction (`world_to_agent` / `agent_to_world`), cadence, and — when solver and decision cadence differ — an explicit `observation_reduce`; ledger quantities declare exactly one `consumer_of_record`. Violations are rejected at construction or raised as `CouplingViolation` at runtime under `fail_loud`.
2. Implement the composable interfaces from `broker/coupling/interfaces.py` (`EventSource`, `ExposureUpdater`, `VulnerabilityModel`, `FinancialLedger`, bundled as `InterfaceBundle`); for a CSDMS-BMI numerical model, wrap it with `BmiEventSource` / `BmiComponent` from `bmi_source.py` (continuous control: `BmiControlSink` in `continuous.py`; spatial grids: `GridEventSource` / `GridProjector`).
3. Wrap with `EnvironmentCouplingAdapter` (`adapter.py`) and inject it as the runner's engine: `ExperimentRunner(sim_engine=adapter)` — `advance_step` pumps world→agent observations through the contract checks; `execute_skill` is a pure committer that only applies already-APPROVED deltas (governance on world-mutating actions runs earlier, as a `builtin_checks` ERROR validator inside the retry loop). Keep the domain-specific adapter under `examples/<domain>/`, gate it with `resolve_coupling_enabled` (`flag.py`), and never add domain vocabulary under `broker/coupling/` — a flag-OFF run must not even import the module.

## Rules that must never break

[broker/INVARIANTS.md](../../broker/INVARIANTS.md) is authoritative and enforced by `broker/tests/test_framework_invariants.py`: memory engines preserve metadata in `retrieve()` (callers that want bare strings must call `retrieve_content_only()`), classification paths are unified, and `broker/coupling/` + generic broker code stay domain-vocabulary-free. Read it before adding any memory engine, audit column, validator module, or domain adapter. Broader orientation: [quickstart](../quickstart.md), [README.md](../../README.md), [DATA.md](../../DATA.md) for data provenance, [CONTRIBUTING.md](../../CONTRIBUTING.md) for workflow.
