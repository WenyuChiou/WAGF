## 2. Per-dimension findings (surviving, with file:line and skeptic disposition)

### Water balance
- **Powell 12 MAF ceiling** — `docs/irrigation_physics.md:15,77-78,182` and README pseudocode state `Q_Powell = max(7, min(Q_raw, 12))`; `_generate_lake_mead_level` (`examples/irrigation_abm/irrigation_env.py:936-949`) computes `powell_release = natural_flow - ub_div_effective` with no such clamp anywhere in the file. Skeptic: **STANDS** — real doc/code gap. Masked downstream by the independent ±3.5 MAF/yr storage-delta clamp (`irrigation_env.py:981-983`), so it doesn't corrupt the elevation trajectory, but the intermediate `Q_Powell` the docs describe is never actually computed.
- **Mexico Minute 323 deepest tier** — `irrigation_env.py:963-974` and the physics doc agree at 0.275 MAF for <1025 ft; real-world Minute 323 at that depth is cited by the reviewer as 0.150 MAF. Skeptic: **PARTLY** — internally consistent (not a code bug), but the external comparison number can't be verified from this offline checkout; keep as an open sourcing question.
- Storage hard-bounds `[2.0, 26.1]` MAF (`irrigation_env.py:985`) clip silently without booking spill/unmet-demand — never reached in-sample, so acceptable as-is.

### Allocation / institutional design
- **Flat curtailment on both basins** — `_apply_curtailment` (`irrigation_env.py:1059-1070`) applies one Mead-tier ratio to every agent regardless of basin; the real DCP shortage-sharing mechanism is Lower-Basin-only (Upper Basin is governed separately via Powell/Compact). Skeptic: **PARTLY REFUTED on "double-constrains"** — numerically verified across all 2,352 UB agent-year rows in the real run that persisted `diversion` matches `request*(1-curtailment_ratio)` exactly (max abs diff 5.8e-11), with zero trace of the Powell pro-rata factor surviving. So agents are not actually cut twice. What **STANDS**: the flat Mead-tier ratio genuinely applies to UB agents with no basin filter, which is an institutional mismatch even though it causes no double-counting in practice.
- **`compact_allocation_check` dead code** — `irrigation_validators.py:266-320` short-circuits whenever `context["basin_allocation"]` is absent; `get_agent_context()` (`irrigation_env.py:600-648`) never injects that key. Skeptic: **STANDS, strongly confirmed** — `compact_allocation_check` has 0 `seen_count` in `validator_health.csv` across the full published run. The per-basin legal Compact allocation values (`upper_basin_allocation`/`lower_basin_allocation`, `irrigation_env.py:44-45`) are used only for display/prompt text, never as a gating constraint anywhere.
- Demand ceiling (item 9 below) also lives conceptually in this dimension — flagged once under world_rules to avoid duplication.

### Agent-environment interaction / timing
- **Powell pro-rata constraint discarded** — `_apply_powell_constraint()` (`irrigation_env.py:1076-1101`) computes a UB pro-rata scale-down from last year's diversions, but `update_agent_request` (`irrigation_env.py:663`), called for every agent every year via `execute_skill`, immediately overwrites `diversion = request*(1-curtailment_ratio)` with no Powell factor. Skeptic: **STANDS**, and is the same mechanism verified numerically above — the per-agent audit-log `diversion` column carries zero Powell information. The aggregate Mead mass balance is unaffected because `_generate_lake_mead_level` independently recomputes `ub_div_effective = min(ub_div_maf, ub_flow_cap, ub_infra_cap)` (`irrigation_env.py:940-943`) from summed diversions — so this is a disaggregated-bookkeeping defect, not a physics bug, but it means summed per-agent UB diversions in the log can legitimately exceed the physically-realized Powell release.
- Precip→inflow same-year vs. diversion→storage one-year-lagged, both inside `_generate_lake_mead_level` (`irrigation_env.py:929-936`) — physically correct (precip is this year's weather, diversion is last year's completed withdrawal) but the asymmetry is documented only in code comments, not Methods.

### Fidelity to Hung & Yang (2021)
- **Cluster centroids unsourced** — `_infer_cluster()` (`examples/irrigation_abm/irrigation_personas.py:456-476`) hardcodes three 4-D centroid points behind a generic comment, no table/page citation. Skeptic: **STANDS** — cannot verify from this repo whether these are the paper's own k-means output or a re-derivation.
- **Realized cluster skew, unrebalanced** — README §5 reports 67 aggressive / 5 forward-looking / 6 myopic of 78 agents; `--rebalance-clusters` (target 50/30/20, `run_experiment.py:590-611`) is opt-in and off in the headline run. Skeptic: **STANDS, confirmed empirically** — pulled year-1 cluster assignments directly from the real seed42 log: exactly 67/6/5, matching README and nowhere near the rebalance target.
- Calibrated `mu/sigma/alpha/regret` feed only `_infer_cluster`, not skill magnitude sampling (a separately-tuned Gaussian per skill/persona does that, `irrigation_env.py:317-322`); `gamma/epsilon/forget` are loaded onto the profile but never read in the LLM run path (only by the separate `run_fql_baseline.py`). Currently undisclosed as such in README/SI.
- `_UB_GROUP_AGENT_COUNTS` (`irrigation_personas.py:631`) hardcoded positional list mirrors the reference's array with no `sum(...) == len(ub_agent_names)` assertion. Skeptic: **STANDS as latent risk, harmless in this run** — counts sum correctly here (58 UB + 20 LB = 78).

### World rules / validators
- **`demand_ceiling_stabilizer` stale-aggregate gap** — `total_basin_demand` is computed once per year in `advance_year()` from last year's finalized `request` values (`irrigation_env.py:590-592`) and copied unchanged into every agent's context for the whole year (`run_experiment.py:221,253`); the 6.0 MAF threshold (`irrigation_validators.py:682`) is checked against this stale, once-per-year number rather than a live running total. Skeptic: **STANDS, confirmed to actually occur** — summing `request` across all 78 agents per year in the real seed42 log shows the aggregate exceeds 6.0 MAF in 34 of 42 years (up to 6.071 MAF in year 6), while the validator fires on nearly every exposed check — i.e. the exact overshoot scenario the rule's own docstring says it exists to prevent is routinely happening in the published data.
- **`water_right_cap` redundancy** — enforced both by the Python builtin (`irrigation_validators.py:44-61`) and an identically-conditioned YAML `identity_rule` (`config/agent_types.yaml:369-375`), evaluated through two independent code paths. Skeptic: **PARTLY** — structurally real double-fire risk, but empirically `water_right_cap` never appears in `failed_rules`/`rules_triggered` across all 3,276 decision rows in the published trace (agents never actually reached their water-right cap), so no metric damage in this dataset — but the redundancy would corrupt rule-frequency counts the moment a run does reach the cap.
- `supply_gap_block_increase` 70% fulfilment cutoff (`irrigation_validators.py:563-588`) has no stated empirical or institutional basis anywhere in code, README, or config (unlike the Interim-Guidelines-cited curtailment ratios or the CRSS-calibrated demand ceiling).
- `strict` profile's `WSA_LABEL`/`ACA_LABEL` rules (`config/agent_types.yaml:344-365`) are parsed from the LLM's own self-reported reasoning, not cross-checked against the environment's actual `drought_index` — only the `grounded_v1` profile's `observed_scarcity_low_wsa_increase` rule does that cross-check.

## 3. Must state in Methods/SI (caveat sentences, ready to paste)

1. "Lake Mead elevation and the basin water balance are produced by a closed-form annual single-reservoir surrogate mass balance, not by coupling to RiverWare/CRSS as in Hung & Yang (2021); diversions are treated as fully consumptive (no return flow)."
2. "Shortage-tier curtailment, triggered by Lake Mead elevation per the Colorado River Interim Guidelines, is applied as a single flat ratio to all agents in both the Upper and Lower Basin; in the real institutional system this mechanism governs Lower Basin deliveries only, while the Upper Basin is separately constrained by the Powell-release/infrastructure pro-rata mechanism modeled here."
3. "The demand-ceiling and demand-floor stability corridors (6.0 MAF / 50% of water right) are framework-added stabilization heuristics, not institutional rules from Hung & Yang (2021); the 6.0 MAF ceiling is checked against the previous year's aggregate demand, not a live intra-year total, and can be — and in the reported run routinely is — exceeded before the check engages the following year."
4. "The 70% fulfilment cutoff used by `supply_gap_block_increase` is an unvalidated modeling choice, not derived from CRSS or the Interim Guidelines."
5. "Calibrated FQL parameters (mu, sigma, alpha, regret) from Hung & Yang (2021) are used only to assign each of the 78 agents to one of three behavioral clusters via nearest-centroid classification; the magnitude of each agent's demand change is drawn from a separately-tuned per-skill Gaussian, not from the paper's calibrated parameters. Cluster centroids were not rebalanced to a target distribution for the reported run; the realized split (67 aggressive / 6 myopic-conservative / 5 forward-looking-conservative of 78) should not be assumed to match the paper's own cluster proportions."
6. "Within each Upper Basin state group, individual agents share identical calibrated behavioral parameters (only water rights and narrative persona text differ), reflecting the state-group resolution at which the source calibration was performed."
7. "Precipitation is generated as a single Upper-Basin-wide signal shared by all Upper Basin agents, rather than per-state-group signals as in the reference model."
8. "In the `strict` governance profile, drought-perception rules (WSA/ACA labels) constrain the LLM's own self-reported scarcity labels and are not cross-checked against the environment's computed drought index; only the `grounded_v1` profile performs that grounding."
9. "A cold-start grace period converts Tier-2 shortage blocks into warnings for simulation years 1-3, making governance strictness non-uniform across the study horizon within the `strict` profile."
10. "Per-agent logged diversion values for Upper Basin agents reflect the pre-Powell-clamp request; the authoritative post-clamp aggregate is the basin-level Powell release computed in the water balance, not the sum of the per-agent diversion column."

## 5. Plain-language summary for the author

The water-balance model is a clearly-labeled stand-in for the full RiverWare simulation the original paper used, and it does the core bookkeeping (how much water comes in, how much goes out, how the reservoir level changes) correctly — that part is solid. Two governance rules, however, behave slightly differently from what their own documentation claims: one rule meant to cap total basin-wide demand at a safe level is checked against last year's numbers instead of this year's, so in the actual published run the basin routinely goes over that cap without the rule catching it; and a separate rule meant to limit how much the Upper Basin can draw gets computed but then gets silently thrown away and replaced before it ever affects an agent's recorded water use. Neither of these breaks the physical water accounting, and neither requires rerunning any experiments to fix in the paper — they just need one or two honest sentences in the Methods or Supplementary Information saying what the code actually does. A few smaller things (an unsourced 70% cutoff number, cluster percentages that were never rebalanced to match the target split, one governance rule that never fires because a piece of data it needs was never wired in) are all worth a similar one-line disclosure rather than a code change. Overall the irrigation model is a defensible, well-documented simplification of the reference study, and the fixes needed before submission are all sentences to add, not code to rerun.
