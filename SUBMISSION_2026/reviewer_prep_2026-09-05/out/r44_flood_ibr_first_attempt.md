## Definition (PI decision, 2026-09-29)

IBR = decisions whose FINAL proposal after retries violates a flood thinking rule, judged against the appraisal given at the FIRST attempt, divided by all decisions (all rows).

- R1: threat (TP) High or Very High AND coping (CP) not Very Low or Low AND action is do_nothing.
- R3: TP Very Low or Low AND action is relocate.
- R4: TP Very Low or Low AND action is elevate_house.
- R5 (already-elevated) is never counted, unchanged from the published metric.
- Source: `.research/design_specs/flood_design_record_2026-09-29.md` ("PI decisions 2026-09-29", items 2 and 4).

## Limitations

1. First-attempt appraisal is recovered from `retry_count` and the chronological order of `failed_rules` (see the script's own module docstring for the code trace establishing that order), not from a per-attempt trace field -- `raw/household_traces.jsonl` was checked directly and carries no richer per-attempt breakdown than the audit CSV already does (verified 2026-09-29 on both an initprop and a non-initprop run).
2. The first-attempt COPING label cannot be recovered at all when a row's first attempt was blocked by R1 (`extreme_threat_block`), because the AS-RUN R1 validator never reads coping. Such rows now carry coping as UNKNOWN (bin MID_OR_UNK, read as 'not low') rather than the FINAL `construct_CP_LABEL` (the pre-fix method, kept only as the lower-bound sensitivity line above, since that final label drifts during retries and under-counts strict's own R1 hits -- see the module docstring REVIEW FIX ROUND). In the primary defaults strict arm this affects 728 of 8786 rows (8.3 percent); 0 in the disabled arm, which never retries at all.
3. 'Coping not Very Low or Low' is read as cp_bin != LOW; a missing or off-vocabulary coping label, AND the now-deliberate UNKNOWN case above, both count as 'not low' -- the wider reading, adopted for lack of positive evidence the coping was actually low.
4. 5 of 8786 rows in the primary defaults strict arm (0.06 percent) are blocked on their first attempt by a rule outside {R1, R3, R4} (elevation_block, precondition_violation, output_schema_violation, or an unparsed 'Unknown' failure) and so cannot be classified as a first-attempt violation either way; they are excluded from the R1/R3/R4 numerator, counted in `n_unresolved`, listed individually (S1, above), never guessed, and always kept in the 'all decisions' denominator. As the S1 listing shows, a row whose FINAL action is do_nothing is the case most plausibly a missed R1 (it would need first TP H/VH, which this script cannot confirm or rule out); rows whose final action is buy_insurance can never be a missed R1/R3/R4 regardless of first TP.
5. A final proposal that never parsed at all after every retry (status REJECTED_FALLBACK) is excluded from the IBR_first and relabel-rate numerators (there is no independent evidence of what it would have proposed) in every case EXCEPT one, corrected 2026-09-29: a REJECTED_FALLBACK row whose ENTIRE `failed_rules` is `extreme_threat_block` alone has every parsed attempt on record as do_nothing (checked against `attempt_skills` in Part 0, 7 of 7 such rows on strict_initprop had an attempt_skills value and all passed; a missing value would raise, never be silently skipped), and the approved definition reads the last recorded proposal, so this IS counted as an R1 violation in the PRIMARY number -- its do_nothing is confirmed, not guessed. For the relabel-rate split specifically, such a row is classified STILL_VIOLATES (never CHANGED or KEPT_RELABELED), since IBR_first already treats it as a violation and there is no final label at all to credit as having improved. The 'excluded' sensitivity line drops these rows entirely instead (the convention this script's own Part 0 validation was run under, since that is what the 139/4,359 and 31.89 percent targets were computed against); it is reported beside the primary number in every table above, never used as the headline.
6. Scope: only the strict, disabled and placebo arms are reported, in the defaults (primary) and v08 (appendix) corpora, matching every arm in `.research/design_specs/flood_design_record_2026-09-29.md` Sec 3.4 marked LANDED with usable per-decision labels. Paraphrase and no-nudge arms are PARTIAL/NOT RUN there; gemma4:12b is NOT RUN at defaults sampling; the traditional rule-based ABM has no LLM appraisal labels at all ('IBR not computable' in the design record) -- none of these are in this report.
7. This script writes only this .md file (no companion .csv), unlike every sibling r-script in this directory, per this task's own constraint against touching any file beyond the two named deliverables.
