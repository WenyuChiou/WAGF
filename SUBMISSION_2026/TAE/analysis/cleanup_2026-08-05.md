# Cleanup adjudication — 2026-08-05

## Plain-language summary

Four audits swept this repository looking for the same failure the project is about: a run, a
number, or a record that looks fine and is not. They found real things. The most consequential is
that in the Nature Water flood experiment, the "with validators" runs and the "without validators"
runs are **not the same random seeds** — the governed arm recorded seeds 42/4202/4203/45/46 while
its control recorded 42/43/44/45/46, and both analysis scripts pair them by folder name, so two of
every five pairs compare unlike with unlike. Two more flood runs turn out to have been produced by
an older version of the code that wrote a different set of columns, and one of them supplies more
than half its group's rejections. Separately, three analysis scripts count only the word
`REJECTED` and silently miss a second rejection label, `REJECTED_FALLBACK`, which is 1.6 % of the
rejections in the headline irrigation cell. On the software side, the response-format check that is
supposed to catch a malformed answer from the language model is wrapped in an error handler whose
log line is commented out — if it ever fails, a decision missing every required field is approved
and written to the audit file as a clean row, leaving no trace at all.

**What is being changed now:** nothing that touches a run's data, a manuscript, the `broker/`
framework, or a published number. Only records — three new dated notes that write down what was
found and where, placed beside the affected runs, plus a superseded banner on the two tracking
documents that still tell a reader the paper is going to a workshop that closed on 2026-08-05.

**What is deliberately not being touched:** the 226 MB quarantine directory, the dead-run partials,
the divergent ministral run and its odd rows, the two odd flood runs, every superseded planning
document, and every results root too small or too unread to be worth being wrong about. None of
them is deleted, moved, or edited. Destroying the evidence that a defect was caught is the worst
thing that could be done in this repository, and several of these directories exist precisely
because a defect *was* caught.

## Scope ruling: what the author's two requests mean here

The author asked for two things. This adjudication reads them narrowly on purpose.

**"Deal with contaminated or outdated records"** means: every run whose value vocabulary, column
schema, seed, or code state differs from its siblings gets a written label beside it naming the
difference and naming the analysis that reads it; and every tracking document that a reader would
take as *current* and that is *wrong* gets corrected. It does **not** mean deleting, moving, or
editing any run. It does **not** mean rewriting documents whose stale dates are correct as history.

**"Make sure the WAGF module and pipeline are clean"** means: the defects found in `broker/` are
enumerated with exact diffs and go through the review gate. It does **not** mean applying them here.
Standing Law 6 makes every `broker/` change a change to published numbers until a mock-LLM run
proves otherwise via `compare_audit_csv`, and none of the proposed diffs has that proof yet.
