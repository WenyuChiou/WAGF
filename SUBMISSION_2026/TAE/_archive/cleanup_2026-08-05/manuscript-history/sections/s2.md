## 2 Setup <!-- page budget: 0.75 pg -->

Both testbeds run the same governed loop. The agent returns an action and a self-reported appraisal of
its situation in one generation, a validator stack screens the proposal against that appraisal and
against the state the simulator recorded, and an ERROR-level violation returns the broken rule and
re-prompts, up to {{CLAIM:retry_budget}} attempts, after which a domain default executes. The rule
under study reads: if the reported water scarcity is high and the reported coping capacity is high, an
increase in demand is forbidden. Its antecedent is a variable the agent writes.

Irrigation is the primary testbed: 78 farm agents over 42 years, {{CLAIM:decisions_per_run}} decisions
per run, a dual-appraisal theory of scarcity and coping, {{CLAIM:irrigation_action_count}} actions from
a large increase to a large decrease, and a water right capping what any agent may withdraw. A
reservoir is coupled to those withdrawals, so an action taken in one year changes the state the next
year's decision is conditioned on. Flood is the second testbed, a cross-theory portability
demonstration running Protection Motivation Theory over {{CLAIM:flood_action_count}} actions on the
same loop. It carries no action-to-environment feedback, so nothing an agent does there alters what a
later decision sees, and it is not a control for enforcement pressure. Identification here is within
irrigation.

The corpus holds {{CLAIM:n_model_configs}} model configurations from {{CLAIM:model_scope}}, each run
with validators on and off. Runs are paired between arms, {{CLAIM:n_seeds}} seeds per arm in most
cells, fewer in two irrigation cells; Table 1 gives *n*.
